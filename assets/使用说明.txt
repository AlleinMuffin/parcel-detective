========================================================================
 面单 VLM 识别与匹配  v2.1.1
========================================================================

【重要声明：识别依赖外部模型】

  本程序自身不含任何 AI 模型，识别能力来自本机的 Ollama 服务与 Qwen 视觉模型。

    1. 必须先安装并启动 Ollama（默认地址 http://localhost:11434）。
    2. 必须已用 ollama pull 拉取所选模型，默认 qwen3-vl:2b-instruct。
    3. 识别效果取决于所部署的模型规格；程序只负责调用与呈现。

  以上任何一条不满足，识别都无法工作。程序会在开始识别前检查并给出报告，
  但不会因此退出。


【怎么启动】

  双击程序目录下的  ParcelDetective.exe  即可。

  界面只有两个标签页：【一键检测】与【信息库】。

  也可以把图片直接拖到 exe 上，或用命令行（见后面的【命令行】一节）。


【一键检测：一次识别一张或一批】

  1. 点【上传图片并识别】，可按住 Ctrl/Shift 多选图片
     （支持 jpg / jpeg / png / bmp / webp）。
  2. 程序先检查模型，再逐张识别并比对信息库。
  3. 结果区会显示：
       · 判定结论（通过 / 待确认 / 人工），整行大字
       · 单号、匹配得分、耗时、判定原因
       · 左侧：本次检测图 与 信息库中对应记录的面单图 并排对照
       · 右侧：「信息对照」逐字段列出 AI 值与库值，鼠标悬停整行高亮
                「AI 提取字段」列出全部 15 个字段，空值也列出
       · 下方：Top-3 候选记录，点某一行即换成它来对照
  4. 多张时用【◀ 上一张】【下一张 ▶】原地切换，不会弹新窗口。
  5. 发现收件方/寄件方被模型弄反时，点【⇄ 对调收/发件方】，
     程序会对调后重新比对、重新判定（阈值与自动流程同一套）。

  耗时：首次识别需等模型加载（约 5~10 秒），之后单张约 2~4 秒。批量是串行的，中途可点【停止】
  （当前这张跑完才停，不会强行打断模型调用）。


【识别模型：三个可选，默认 2B Instruct】

  界面顶部「识别模型」下拉框：

    · qwen3-vl:2b-instruct        默认，速度优先（约 1.8 GB）
    · qwen3-vl:4b-instruct-q4_k_m 平衡（需自行 ollama pull）
    · qwen3-vl:8b-instruct-q4_k_m 精度优先，最慢（需自行 ollama pull）

  使用规则：

    1. 默认就是 2b-instruct，不需要任何设置。
    2. 切换模型后，程序会立即检查两件事：
         (1) Ollama 服务是否在运行；
         (2) 这个模型是否已经安装。
       检查过程中下拉框会短暂禁用（一般不到 1 秒；服务无响应时最多 5 秒）。
    3. 检查结果：
         · 通过 -> 右侧显示「已就绪」，绿色
         · 失败 -> 显示「不可用」，红色，并弹出「模型可用性异常报告」，
           报告里写明原因和该执行的命令；同时写入下方处理日志。
           程序不会退出，也不会影响已经识别的结果，可以切回其它模型继续用。
    4. 每次开始识别前会再复查一次模型（5 分钟内的检查结果直接复用）。
       模型不可用时，本次识别会被取消并说明原因，避免白等三轮重试。

  注意：

    · 本机默认只安装了 2b-instruct。切换到 4B/8B 时提示「没有找到模型」是正常的，
      先执行 ollama pull 对应模型即可。
    · 模型选择不会保存。关掉程序再开，回到默认的 2b-instruct。
      如需固定，用环境变量 PARCEL_AI_MODEL，或命令行 --model。
    · 换更大的模型不会自动变准。4B/8B 需要更多显存，速度也更慢；
      本项目没有对这两个模型做准确率实测，不宣称效果提升。
    · 模型名必须与 ollama list 里的完全一致（含 :4b-instruct-q4_k_m 这类后缀）。


【判定结论怎么读】

    ≥ 0.85           通过      证据充分，可自动打单/放行
    0.60 ~ 0.85      待确认    人工从候选里核一下是哪一件
    < 0.60 或没字段  人工      信息不足或匹配度过低，转人工处理

  阈值只有一处实现（程序内部），界面、对调、命令行都用同一套，不会出现两处标准。


【信息库】

  信息库是匹配判定的依据。切到【信息库】标签页：

    · 搜索框输入任意片段即可，不必指定字段。例如：
        单号后缀 25482     电话尾号 1234     地址关键词 武侯区
      带空格或横杠也能搜到。
    · 勾选「只看破损」只显示破损样本。
    · 表格里双击单元格可以直接改，改完自动保存。
    · 【查看图片】/ 内嵌预览：显示该记录关联的面单照片。
    · 【修复图片路径】：照片被挪过位置、路径失效时，选图片所在目录批量修复。
    · 【导入 JSON 到数据库】：可多选 .json，批量导入，不重新识别。
        完成后提示：成功 X 条，跳过 X 条（重复），失败 X 条。
        单号已存在的记录默认跳过（忽略空格与横杠差异）。
        支持：单个对象、对象数组、外层包 records、以及本程序导出的结果。
    · 【导出 CSV】：导出当前筛选结果或全库，CSV 带 BOM，Excel 直接打开不乱码。

  数据位置：

    %LOCALAPPDATA%\ParcelDeskewOCR\parcels.db

  便携用法：如果 exe 同级目录存在 parcels.db，程序优先用它（整个文件夹拷到
  别的电脑也能带着数据走）。

  自动备份：每天把数据库复制一份到

    %LOCALAPPDATA%\ParcelDeskewOCR\backup\parcels_日期.db

  保留最近若干份（默认 7 份）。备份故意放在程序目录之外：升级换版本时整个
  程序文件夹会被替换，放在里面的备份会一起没掉。

  升级/换版本前：把旧的 parcels.db 拷到新版本 exe 旁边，或先导出全库 CSV。
  忘了也不要紧，自动备份里还有。


【命令行】

  图形界面：      ParcelDetective.exe

  命令行识别：    ParcelDetective.exe --ai 面单1.jpg 面单2.jpg [--db x.db]
                                     [--top 3] [--model 模型名] [--save]
                                     [--out 结果.json]

                  --model  指定模型（优先级最高）
                  --save   只有判定「通过」时才写入信息库
                  --out    把完整结果写成 JSON

  只检查服务：    ParcelDetective.exe --ai-check
                  ParcelDetective.exe --ai-check --model qwen3-vl:4b-instruct-q4_k_m

  列出模型：      ParcelDetective.exe --models
                  显示三个可选模型、默认项、以及本机是否已安装

  信息库统计：    ParcelDetective.exe --stats [--db x.db]

  退出码：

    --ai          0 = 全部「通过」；1 = 存在待确认/人工；2 = 参数或运行错误
    --ai-check    0 = 服务与模型就绪；1 = 不可用
    --models      0 = 服务可用；1 = 服务不可用

  输出编码：直接看控制台是系统代码页（中文正常）；重定向到文件或管道时
  自动切 UTF-8，下游按 UTF-8 读不会乱码。


【环境要求】

  · Windows 10 / 11 64 位。
  · 本机已安装 Ollama 并至少拉取一个视觉模型（默认 qwen3-vl:2b-instruct）。
  · 8 GB 显存可跑 2B；4B/8B 需要更多显存，显存不足时 Ollama 会自动退回 CPU
    （能跑，但明显变慢）。
  · 程序目录约 300 MB，已包含 Python 运行库，不需要另装 Python。


【不要只拷 exe】

  ParcelDetective.exe 必须和同目录下的  _internal\  一起使用。
  单独把 exe 拷走会无法启动（运行库都在 _internal 里）。

  要拷贝给别人，请拷【整个 ParcelDetective 文件夹】，或使用打包好的 .7z。


【常见问题】

  1. 提示「连不上 Ollama 服务」
     -> Ollama 没启动。开始菜单打开 Ollama，或命令行执行 ollama serve，
        确认系统托盘出现 Ollama 图标后重试。

  2. 提示「没有找到模型 qwen3-vl:2b-instruct」
     -> 执行 ollama list 看有没有；没有就 ollama pull qwen3-vl:2b-instruct。

  3. 切到 4B/8B 后显示「不可用」
     -> 本机没有这两个模型，属正常。先 ollama pull，或切回 2B。
        可用 --models 查看已安装清单。

  4. 第一次识别很慢（20 秒以上）
     -> 模型正在加载进显存，之后每张会快一些。

  5. 提示显存不足 / out of memory
     -> 关掉占显存的程序，或换回 2B 模型；Ollama 也会退回 CPU 跑。

  6. 判定总是「待确认」，分数 0.5~0.7
     -> 多为信息库字段脱敏、或面单号码与库中号码本就不同。
        先看「信息对照」确认库中那一条本身对不对，再决定是否人工放行。

  7. 收件人和寄件人反了
     -> 模型偶发问题。点【⇄ 对调收/发件方】，程序会重判。

  8. 新检测的图片不显示 / 右侧仍显示上一张的库图
     -> v2.0.3 起已修复刷新逻辑；若仍出现，确认用的是最新 exe。
        右侧提示分三种：「未匹配到库中记录」「该记录没有信息库图片」
        「找不到图片文件」。

  9. 信息库图片打不开
     -> 图片被挪走或改名。点【修复图片路径】重新指定目录。

  10. 改了代码但行为没变
     -> 忘了重新打包。执行 python build/build_exe.py。

  11. 打包报 PermissionError [WinError 5]
     -> 旧的 ParcelDetective.exe 还在运行，先结束进程再打包。


【隐私与写入】

  程序不联网上传图片，不写注册表。只读你选择的图片文件。
  写入范围仅两处：
    · 信息库数据库（默认在 %LOCALAPPDATA%\ParcelDeskewOCR\）
    · 同目录下的自动备份


【技术信息（排错用）】

  版本            2.1.1
  界面            PyQt5（Qt 5.15）
  识别            Ollama + Qwen 视觉模型（默认 qwen3-vl:2b-instruct）
  比对            五组加权：运单号 0.40 / 收件电话 0.20 / 收件地址 0.20 /
                  收件姓名 0.10 / 其它 0.10
  判定阈值        0.85 通过 / 0.60 待确认
  数据库          SQLite，表 parcels，20 列
  默认数据库      %LOCALAPPDATA%\ParcelDeskewOCR\parcels.db
